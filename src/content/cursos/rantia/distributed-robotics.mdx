<Body>

### DDS vs MQTT

- — **DDS/ROS2**: comunicação interna entre nós, sensores e atuadores do robot.
- — **MQTT**: protocolo lightweight publish-subscribe para IoT e integração cloud.

São complementares, não substitutos. <Highlight>MQTT não substitui DDS</Highlight> — é a armadilha mais comum.

### Bridge ROS2-MQTT

Liga os dois mundos: <Kbd>ROS2 topic ↔ bridge node ↔ MQTT broker ↔ IoT/cloud clients</Kbd>

O bridge seleciona tópicos, transforma formatos, controla taxas e gere timing. Não deve reencaminhar todos os tópicos de alta frequência indiscriminadamente.

### Riscos de bridging

Latência, dados obsoletos, race conditions, sobrecarga de bandwidth e QoS mismatch. O bridge deve ser seletivo e controlado.

### Data fusion e shared world model

Um modelo partilhado do mundo pode combinar dados de robot, sensores e IoT numa representação comum para decisões. Isto é data fusion ao nível do sistema.

</Body>

<Callout icon={Network} title="armadilha de exame: MQTT substitui DDS?">
  NÃO. DDS é para comunicação interna ROS2 (baixa latência, real-time). MQTT é para IoT/cloud (lightweight, broker-based). O bridge liga os dois. Se o exame pergunta "qual a vantagem de integrar ROS2 com MQTT", a resposta é estender a comunicação para IoT/cloud, não substituir DDS.
</Callout>

</Marginalia>
