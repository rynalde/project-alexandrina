ROS2 é uma das **áreas mais fortes de exame**. Organiza software robótico como nós que comunicam através de tópicos, serviços e ações.

### Conceitos fundamentais

- — <Highlight>Nó (Node)</Highlight>: unidade executável que realiza uma tarefa. Exemplo: nó de câmara publica imagens.
- — <Highlight>Tópico (Topic)</Highlight>: canal nomeado para mensagens publish-subscribe. Exemplo: `/cmd_vel` transporta comandos de velocidade.
- — <Highlight>Publisher</Highlight>: nó que envia mensagens para um tópico.
- — <Highlight>Subscriber</Highlight>: nó que recebe mensagens de um tópico.
- — **Serviço**: comunicação request-reply síncrona.
- — **Ação**: comunicação goal-feedback-result para tarefas longas.

### DDS e QoS

ROS2 usa <Highlight>DDS (Data Distribution Service)</Highlight> para discovery e comunicação. Não requer roscore/ROS Master (diferença-chave vs ROS1). QoS controla comportamento de comunicação (reliability, latency).

### Comandos ROS2 essenciais

| Tarefa | Comando |
|---|---|
| Listar nós | <Kbd>ros2 node list</Kbd> |
| Listar tópicos | <Kbd>ros2 topic list</Kbd> |
| Info de tópico | <Kbd>ros2 topic info /topic_name</Kbd> |
| Echo de tópico | <Kbd>ros2 topic echo /topic_name</Kbd> |
| Frequência | <Kbd>ros2 topic hz /topic_name</Kbd> |
| Listar pacotes | <Kbd>ros2 pkg list</Kbd> |
| Executar nó | <Kbd>ros2 run demo_nodes_cpp talker</Kbd> |

### Armadilhas ROS1 vs ROS2

Em exame, verifique SEMPRE se a pergunta é ROS1 ou ROS2. Comandos ROS1 como `rostopic echo`, `rostopic type` e `rossrv show` NÃO são válidos em ROS2. ROS1 usa `roscore`/ROS Master e TCPROS. ROS2 usa DDS e não precisa de roscore.
