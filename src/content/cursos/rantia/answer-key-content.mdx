### Parte B — Respostas

**21.** Sistema ciber-físico: integra computação e comunicação com um processo físico, com influência bidirecional. Exemplo: controlador de máquina que ajusta comportamento com base em feedback de sensores — o sensor afeta o software e o software controla o atuador.

**22.** <Highlight>Gazebo</Highlight>: simulador 3D com motor de física, sensores simulados e plugins ROS. Simula o mundo virtual completo. <Highlight>RViz2</Highlight>: visualizador de dados ROS2 (TF, sensores, odometria, markers). NÃO simula — apenas mostra dados. Ambos são usados no desenvolvimento, mas para fins diferentes.

**23.** Fases: (1) DHT11 ligado ao ESP32 via GPIO com pull-up. (2) ESP32 lê temperatura/humidade no loop(). (3) ESP32 liga-se a WiFi e broker MQTT. (4) Publica dados via MQTT para tópico `sensors/dht11/temperature`. (5) Cloud ingere dados via broker. (6) Dashboard subscreve tópico e mostra dados em tempo real.

**24.** Bridging indiscriminado de todos os tópicos causa: sobrecarga de bandwidth (tópicos de alta frequência como câmara), latência adicionada, dados obsoletos, possíveis race conditions e QoS mismatch entre DDS (real-time) e MQTT (IoT lightweight). O bridge deve selecionar tópicos relevantes, controlar taxas e transformar formatos.
